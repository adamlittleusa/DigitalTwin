# adambuilds.ai Site Implementation Plan (sub-project 4a)

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `https://adambuilds.ai`: a dark, Linear-like portfolio whose front page toggles between six agent architecture buckets and use-case buckets derived from project files, with pattern, use-case, project, About, and Writing pages, built from MDX in the repo and deployed by Vercel.

**Architecture:** Next.js App Router (TypeScript) under `apps/web`. Content is MDX under `apps/web/content/` read by a typed loader (`gray-matter` + Zod) and rendered with `next-mdx-remote-client`. A `tokens.css` holds the design system; a handful of components consume it. Every page is static. CI lints, typechecks, tests, and builds; Vercel deploys.

**Tech Stack:** Next.js 16, React, TypeScript, `geist` fonts via `next/font`, `gray-matter`, `zod`, `next-mdx-remote-client`, Vitest, ESLint. Node 24. Vercel. GoDaddy DNS.

**Spec:** `docs/superpowers/specs/2026-09-06-site-design.md` (the handoff document; read it first, especially sections 5 to 9).

## Review-driven deviations, recorded during execution

- **Task 1.** `create-next-app@16` needed `--turbopack --no-experimental-react-compiler` to run non-interactively. It generates `AGENTS.md`/`CLAUDE.md` inside `apps/web` (and `next dev` regenerates them); both are gitignored.
- **Task 2.** `--text-3` became `#7b8194` (the spec's `#6b7080` failed 4.5:1). "Use cases" gets `aria-current` via `useSearchParams` inside a `Suspense` with a static fallback.
- **Task 3.** `--draw-dash` token shared by the SVG and the keyframe; marker ids scoped with `useId()`; US spelling; the autonomous-agent write-up says the knowledge is loaded whole (it does not "choose files").
- **Task 4.** `z.url()` (Zod 4). The loader normalises YAML `Date` values to `YYYY-MM-DD`. `next-mdx-remote-client/rsc` exports `evaluate`, not `compileMDX`; `src/content/mdx.tsx` wraps it and throws on error so a bad MDX file fails the build. About keeps recorded reasons for leaving (the twin's boundary), never the Corelight reason.
- **Task 6.** The gallery is static: both grids prerendered, `ViewToggle` reads the query on the client and sets `data-view`; a `StaticViewToggle` fallback keeps the toggle in the HTML. `dynamicParams = false` on every dynamic route. The OG image resolves the Geist TTF through `process.getBuiltinModule("node:module")` because Turbopack rewrites `createRequire().resolve` and `geist` does not export its `package.json`.
- **Task 7.** Built pages are flat `.html` files under `.next/server/app`; the link check special-cases `/favicon.ico`, `/_next/`, and `/opengraph-image`.

## Conventions

- Work in `apps/web`; `npm` commands run there. Git from the repo root. Branch `feat/site`.
- Commit messages: conventional-commit prefix; trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- No Tailwind, no UI library, no icon packs. All colours, sizes, and fonts come from `tokens.css` variables. Anything that looks like a template (gradient blobs, glow, card grids with stock icons) is wrong.
- Every page must be static (`next build` output shows `○` or `●`, never `ƒ`).
- Write for Adam's review: the six pattern write-ups and the About page are his voice; mark them "draft for Adam" in the PR.
- Tests: Vitest for the loader and derivation; `npm run build` is the integration test.
- Never touch `apps/twin`, `knowledge/`, or `.env`.

### Task 4: Content loader and launch content

- [ ] `src/content/schema.ts` (Zod):

```ts
import { z } from "zod";
import { PATTERN_KEYS } from "@/patterns";
const slug = z.string().regex(/^[a-z0-9]+(?:-[a-z0-9]+)*$/);
export const useCaseSchema = z.object({ slug, label: z.string().min(1), description: z.string().min(1) });
export const projectSchema = z.object({
  title: z.string().min(1), slug, summary: z.string().min(1),
  architecture: z.enum(PATTERN_KEYS), useCase: useCaseSchema,
  status: z.enum(["live", "building", "retired"]),
  date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  tryUrl: z.string().url().optional(), repoUrl: z.string().url().optional(),
}).strict();
export const writingSchema = z.object({
  title: z.string().min(1), date: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  summary: z.string().min(1), draft: z.boolean().default(false),
}).strict();
export type ProjectMeta = z.infer<typeof projectSchema>;
export type WritingMeta = z.infer<typeof writingSchema> & { slug: string };
```

- [ ] `src/content/load.ts`: `contentDir(kind)` resolving `process.cwd()/content/<kind>`; `loadProjects(dir?)` reads every `*.mdx`, parses with `gray-matter`, validates, checks the frontmatter `slug` equals the file stem, rejects duplicate slugs, returns `{ meta, body }[]` sorted by `date` ascending then slug; `loadProject(slug)`; `loadWriting(dir?, { includeDrafts })` (slug from the file stem; drafts excluded unless `includeDrafts`, which the pages pass as `process.env.NODE_ENV !== "production"`); `loadAbout()` reading `content/about.mdx`. Every failure throws an `Error` whose message starts with the file path. Functions take an optional directory so tests use fixtures.
